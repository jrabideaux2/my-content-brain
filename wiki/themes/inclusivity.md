# Theme: Inclusivity

**Definition:** Content that reflects and respects the full diversity of Intuit's customer base — in language, naming, imagery, and the assumptions embedded in UI copy.

**Why this theme matters:** Exclusionary defaults are often invisible to the person who wrote them. "Normal" in product copy often means white, male, able-bodied, American English, heterosexual, and neurotypical — which describes a narrow slice of actual users. Inclusive content requires actively examining those defaults.

---

## Key principles (Intuit)

### Lead with curiosity and empathy
- Ask how individuals identify when possible and appropriate; don't assume
- Recognize that inclusive language evolves — mistakes are learning opportunities, not failures
- Don't assume one term represents an entire group ("Latinx" is not preferred by all Latin communities)

### Gender-neutral language
- Address customers as "you" (second person) — avoids gendered pronouns entirely
- Use "they/them/their" when third person is required and gender is unknown
- Replace: "sir/ma'am" → "folks," "everyone," "team"
- Replace: "guys/dudes" → "everyone," "folks," "team," "y'all" only if appropriate to voice
- Replace: "men and women" → "everyone," "people"
- Replace: "boys and girls" → "children," "siblings"
- Replace: "his/her" → their; rewrite to use the name instead when possible

### Terminology updates
Replace outdated terms in copy and UI labels:

| Avoid | Use instead |
|---|---|
| "adopted parent" | "parent" |
| "grandfather clause" | "legacy" |
| "Indian" (for Indigenous people) | "Indigenous" (unless referring to the country) |
| "crippled/handicapped" | "disabled" or "person with a disability" |
| "geezer/elderly" | "older person" |
| "wheelchair-bound" | "person who uses a wheelchair" |
| "sanity check" | "confidence check," "gut check" |

### Representation in examples
- Use ethnically and gender-diverse names in sample data (not always "John Smith")
- Intuit has a "Name in Lights" program — use employee names for sample data
- Include varied ethnicities, genders, ages, body types, and abilities in imagery
- Examine whose family structures appear in examples (not only two-parent, heterosexual households)

### Requesting sensitive information
- Collect demographic data only when legally required
- Include "why we need this" tooltips when asking sensitive questions
- For gender identity fields: offer Female, Male, Non-binary/Other (not just "Other")
- Make title fields optional and include gender-neutral option (Mx)

---

## What to watch for in reviews

- Names in example data that are all Western/Anglo
- "He" or "she" used as a default pronoun for customers
- Family structure assumptions (e.g., "your spouse" when "your partner" includes more people)
- Error messages that assume a specific cultural context or financial norm
